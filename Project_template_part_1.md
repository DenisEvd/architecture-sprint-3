# Задание 1. Анализ и планирование

Чтобы составить документ с описанием текущей архитектуры приложения, можно часть информации взять из описания компании условия задания. Это нормально.

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Получение информации об отопительной системе
- Обновление конфигурации отопительной системы
- Включение/выключение отопления
- Установка требуемой температуры

**Мониторинг температуры:**

- Получение текущей температуры

### 2. Анализ архитектуры монолитного приложения

Приложение написано на Java с использованием фреймворка Spring. Для хранения данных используется СУБД PostgreSQL. Взаимодействие с пользователем происходит с помощью REST API. Сервисы и контроллеры состоят из одного общего компонента и для отопительных систем, и для мониторинга температуры.

### 3. Определение доменов и границы контекстов

Текущий монолит содержит один домен, который можно назвать "Контроль температуры".

### **4. Проблемы монолитного решения**

- В текущем монолите единственным способом указания актуальной температуры, является обновление целой дто отопительной системы. Я полагаю, что потенциально в сервис могут приходить сотни, тысячи или даже десятки тысяч обновлений температуры каждую секунду. Текущую реализацию будет трудно масштабировать и поддерживать.
- Трудно масштабировать конкретно ту часть, которая занимается сбором данных с датчиков.
- Из-за сильной привязки температуры к отопительной системе, при попытке изменить логику работы с температурой легко, например, сломать включение и выключение отопительных устройств.
